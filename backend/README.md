# Eco-Sync Backend

FastAPI backend for the Eco-Sync industrial surplus marketplace.

**Status:** Step 1 (foundation) + Step 2 (authentication) completed, plus
production hardening and frontend-integration fixes from the latest session.
Materials, requests, chat, and AI matching are **not** implemented yet.

---

## What is implemented

### Step 1 — Foundation (done)
- FastAPI app with automatic Swagger docs (`/docs`, `/redoc`)
- Settings loaded from `.env` via `pydantic-settings` (DB, JWT, CORS)
- Async MongoDB Atlas connection via Motor + Beanie
- Startup pings the DB (fails fast on bad config) and closes on shutdown
- CORS middleware (allowlist driven by `CORS_ORIGINS`)
- Health check: `GET /` returns `{ "status": "Backend Running", "database": "Connected" }`

### Step 2 — Authentication (signup + login, done)
- `POST /api/auth/signup` — register a user (unique email, bcrypt-hashed password)
- `POST /api/auth/login` — verify credentials and return a JWT access token
- JWT sign/verify via `python-jose`; secrets from environment
- `get_current_user` dependency that resolves the caller from a Bearer token
  (ready for reuse by future modules)

### Latest session (production hardening + integration)
- **User model merged** to include both the auth fields and the spec fields
  (`name`, `company`, `location`, `updated_at`, `role` defaults to `"user"`)
  without breaking the working auth module.
- **`schemas/user.py` added** — dedicated `UserSignup`, `UserLogin`,
  `UserResponse`, `Token` models (spec-aligned, standalone).
- **`security.py` hardened** with production comments around bcrypt
  (automatic salt, constant-time verify, `deprecated="auto"` for hash migration).
- **Frontend compatibility fixed** — the signup endpoint accepts the frontend's
  payload (`companyName`, `city`) via Pydantic aliases, and `full_name` falls
  back to the company name so the React app signs up successfully (was HTTP 422).
- **Login verified working** against the frontend contract
  (`access_token` + `user.role`).

## Setup

### 1. Create a virtual environment

```bash
python -m venv venv
```

Activate it:

- **Windows (PowerShell):** `venv\Scripts\Activate.ps1`
- **Windows (cmd):** `venv\Scripts\activate.bat`
- **macOS / Linux:** `source venv/bin/activate`

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment variables

```bash
copy .env.example .env   # Windows
# or
cp .env.example .env     # macOS / Linux
```

Edit `.env`:

```
MONGO_URI=mongodb+srv://<username>:<password>@<cluster-address>/?retryWrites=true&w=majority
MONGO_DB_NAME=ecosync
JWT_SECRET_KEY=<long-random-string>
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60
CORS_ORIGINS=http://localhost:5173,http://localhost:3000
```

Generate a strong secret with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

> Create the cluster and DB user in [MongoDB Atlas](https://www.mongodb.com/atlas)
> and whitelist your IP under *Network Access*.

### 4. Run the server

From the `backend/` directory:

```bash
uvicorn app.main:app --reload
```

The app starts on `http://localhost:8000`.

## API

### Health check — `GET /`

```json
{ "status": "Backend Running", "database": "Connected" }
```

### Signup — `POST /api/auth/signup`

Creates a user. `email` must be unique; `password` must be ≥ 8 chars.
The endpoint accepts **both** the backend field names and the frontend's names
(`companyName`, `city`); it also accepts both `full_name` and `name`.

Request body:

```json
{
  "name": "Ravi Kumar",
  "company": "Acme Industries",
  "email": "seller@example.com",
  "password": "supersecret123",
  "location": "Mumbai"
}
```

> The frontend sends `{ companyName, email, password, role, city }`, which the
> backend maps via aliases (`companyName` → `company_name`, `city` → `address`).

Response `201`:

```json
{ "message": "User created successfully" }
```

Errors:
- `409` — email already registered
- `422` — invalid email, missing required fields, or password < 8 chars

### Login — `POST /api/auth/login`

Response `200`:

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer",
  "user": {
    "id": "<user-id>",
    "full_name": "Ravi Kumar",
    "company_name": "Acme Industries",
    "email": "seller@example.com",
    "role": "seller",
    "phone": "9876543210",
    "address": "Mumbai",
    "created_at": "2026-01-01T00:00:00Z"
  }
}
```

Errors: `401` for an unknown email or incorrect password.

## Authentication dependency

`app/dependencies/auth.py` exposes `get_current_user`, which:

- Reads `Authorization: Bearer <token>`
- Verifies and decodes the JWT
- Loads the user from MongoDB
- Raises `401` for missing, invalid/expired tokens or unknown users

Future modules (materials, requests, chat, AI matching) reuse it via
`Depends(get_current_user)`.
